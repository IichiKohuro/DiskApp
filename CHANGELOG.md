- Один экземпляр: `Mutex` и именованный канал, повторный запуск передаёт аргументы первому экземпляру; метки времени старта и показа окна поиска в журнале; файловый sink Serilog в режиме `shared`.
- Спайки S3 (Kestrel в процессе) и S4 (FTS5 trigram, 1 млн записей) в `spikes/` с результатами; ADR 0002–0005; тестовый проект `tests/DiskApp.Desktop.Tests`.
- README: раздел «Статус» с таблицей замеров этапа 0 против бюджетов и бейджи; ARCHITECTURE: схема запуска процесса по коду, цепочка регистрации хоткея, состав оболочки и интерфейса, итоги спайков. Ветка `main` на GitHub защищена от принудительной отправки и удаления.
- `DiskApp.Core`, этап 1: модель домена (`Root`, `FileEntry`, `FileKind` с таблицей расширений и переопределениями, `Tag`, `Favorite`, `UsageStat` с frecency, `Collection`, `ExclusionRule`), `PathNormalizer` (буква диска, разделители, `..`, UNC, префикс `\\?\`), `RootValidator`, `Result`/`DomainError`, модель запроса и результатов поиска, интерфейсы репозиториев и платформенных сервисов, шина событий `IndexEventBus`, модель настроек `AppSettings`.
- `DiskApp.Infrastructure`, этап 1: SQLite — схема V001 с FTS5 trigram по имени и `name_folded`, мигратор на встроенных скриптах, фабрика соединений с PRAGMA, единственный писатель `SqliteWriter`, `SqliteDatabase` с проверкой целостности и карантином повреждённого файла, репозитории записей, корней, статистики, избранного, тегов, коллекций и истории запросов; `AppPaths` (обычный и портативный режим); `JsonSettingsStore<T>` с миграциями, атомарной записью и подписками.
- Бенчмарки `tests/DiskApp.Benchmarks`: вставка 100 тыс. записей 4,07 с (бюджет 5 с), переименование поддерева на 50 тыс. записей 184 мс (бюджет 200 мс). Тестов 370.
- Индексация, этап 2: `DirectoryScanner` (параллельный обход по типу диска, исключения по glob, скрытые и системные, глубина, junction без обхода или с защитой от циклов, пауза, фоновый приоритет), `ScanPipeline` (mark-and-sweep через ограниченный канал, сохранение непрочитанных папок), `ReconcileRunner` (сверка по разнице с индексом), наблюдатель `FileSystemRootWatcher` + `ChangeCoalescer` + `ChangeApplier` (склейка событий, переименования с сохранением идентификаторов), `IndexerService` (очередь задач по дискам, офлайн-корни, пауза, пересканирование, пересборка), журнал `scan_log`, признак облачных заглушек, генератор тестовых деревьев. 100 тыс. файлов индексируются за 4,5 с. Тестов 504.
- Поиск, этап 3: `QueryParser` (слова, фразы, фильтры `ext`, `type`, `in`, `root`, `size`, `modified`, `created`, `is`, `tag`, `fav` со значениями на RU и EN, отрицание, диапазоны, регулярные выражения, позиции токенов), `SearchPlanner`, исполнение в SQLite `SqliteSearchIndex` (FTS5 trigram от 3 символов, префикс по `name_folded` для 1–2, фильтр по папкам диапазонами путей, прерывание по отмене и таймауту, подсчёт параллельно выборке), `SearchRanker` с пресетами «По имени», «Недавнее», «Сбалансированно», `FuzzyMatcher` для опечаток, подсветка имени и пути, `SearchService` с курсорами, кэшем уточнения, подсказками и историей. Golden-тесты ранжирования и проверка бюджета `search-budget`: p95 от 1,9 до 44,5 мс на 1 млн записей. Тестов 761.
- Сервер, этап 4: `DiskAppServerHost` — Kestrel внутри процесса десктопа на `127.0.0.1:0`, общий DI-контейнер, открытие базы и индексатор до приёма запросов, `/health`, ошибки в формате ProblemDetails. REST API `/api/v1`: корни и индекс (с паузой отдельного корня), поиск с курсорами, подсказки и история, записи (карточка, содержимое папки, обзор по пути, содержимое с Range, иконки с ETag, действия оболочки), избранное, теги, коллекции, настройки (JSON Merge Patch), сведения о приложении; OpenAPI и Scalar при разработке. Контракты `DiskApp.Contracts` с JSON source generation и снимками в тестах.
- Хаб SignalR `/hubs/diskapp`: подписка на корень, состояние при подключении, ход индексации, смены состояния корней, изменения папок пакетами раз в 250 мс, ход, конфликты и завершение операций, настройки.
- Файловые операции: очередь копирования, перемещения (в пределах тома и между томами), переименования, удаления в корзину и создания; конфликты Ask, Skip, Overwrite, KeepBoth; отмена посередине без недописанных файлов; возврат результата; загрузка файлов; немедленная сверка индекса.
- Защита локального режима: только loopback, проверка `Host` и `Origin`, токен сессии за флагом, пути только внутри корней (в том числе через junction), лимиты размеров.
- Десктоп запускает сервер внутри процесса после показа трея; аргумент `--exit` завершает запущенный экземпляр. Бенчмарк `api-budget`: поиск через API p95 4–46 мс на 1 млн записей. Тестов 891.
- Клиентская библиотека, этап 5: `IDiskAppApi` и `HttpDiskAppApi` со всеми операциями API, ошибки ProblemDetails как `DiskAppApiException`, повторы только для GET и таймауты (Microsoft.Extensions.Http.Resilience), загрузка и скачивание с прогрессом; `DiskAppHubConnection` с переподключением без предела, восстановлением подписок и буфером событий; адрес сервера внутри процесса или заданный; `AddDiskAppClient`. Тестов 901.
- Быстрый поиск, этап 7 (7.1–7.3, 7.7): окна работают с индексом через клиент API (`ApiSearchService`); пустой запрос — секции «Недавно открытые», «Закреплённые», «Недавно изменённые»; бейдж недоступного корня и облачной заглушки; ход индексации в строке состояния и кнопка «Повторить» при ошибке связи; список перечитывается при каждом показе окна.
- Действия над файлом из быстрого поиска с клавиатуры и из контекстного меню: показать в Проводнике (`Ctrl+Enter`), «Открыть с помощью» (`Shift+Enter`), свойства (`Alt+Enter`), запуск от имени администратора (`Ctrl+Shift+Enter`), копировать файл (`Ctrl+C`) и путь (`Ctrl+Shift+C`), закрепить (`Ctrl+P`), переименовать (`F2`), в корзину (`Del` с подтверждением), история запросов по `↑` в пустом поле, `Ctrl+Home/End`; итог — уведомлением в окне поиска. Карта клавиш — `QuickSearchKeyMap`.
- `WindowsPlatformShell`: действия оболочки Windows на STA-потоке, корзина только на локальных жёстких дисках, файлы в буфер обмена в формате Проводника.
- Иконки и миниатюры, этап 7.4: `WindowsIconProvider` (иконки типов из системного списка изображений с кэшем PNG на диске, свои иконки программ и ярлыков, миниатюры через `IShellItemImageFactory`), в интерфейсе — кэш растров и элемент `FileIcon` с заглушкой по виду файла.
- Фильтры и подсказки, этап 7.5: чипы вида, даты и корней над результатами (`Ctrl+F`), дополнение фильтров по подсказкам сервера (`Tab`), история запросов с удалением, справка по запросу `?`.
- Перетаскивание, этап 7.6: результаты перетаскиваются в Проводник, браузер и мессенджер (копия; `Shift` — перенос, `Alt` — ярлык); файлы, брошенные на папку в результатах, копируются туда.
- Главное окно, этапы 8.1–8.3: поиск в заголовке (`Ctrl+E`) и состояние индекса по событиям сервера; главная с карточками корней (сводка, пересканирование, пауза), добавлением папок и списками закреплённых и изменённых за сутки; страница «Обзор» — дерево папок, список и плитка, крошки, адресная строка, история, сортировка, фильтры, выбор нескольких записей и действия над ними. `GET /api/v1/roots/{id}/stats`, аргумент запуска `--page`.
- Операции, этап 8.4: страница «Операции» с ходом, отменой и повтором; диалог конфликтов («заменить», «пропустить», «оставить оба», «для всех»); `Ctrl+Z` для последнего переименования и перемещения; вырезать, копировать и вставить, новая папка и новый файл по шаблону, перетаскивание в «Обзоре» и из Проводника; полоса операций в главном окне и сводка в подсказке трея.
- «Добавить», этап 8.5: окно выбора папки для файлов, брошенных на главную, пришедших из «Отправить» или меню Проводника (`--import`), и для `Ctrl+Shift+V` (текст, Markdown, изображение или файлы из буфера обмена); раздел настроек `add` («Входящие», недавние места, шаблон имени); переключатели интеграций с Проводником: «Отправить», контекстное меню, ссылки `diskapp://`; аргумент `--path`.
- «Сохранить», этап 8.6: экспериментальный Quick Switch (ADR-0008) — в диалоге «Сохранить как» или «Открыть» любой программы `Ctrl+Alt+G` открывает выбор папки в быстром поиске, и диалог переходит в выбранную папку с прежним именем файла. Выключен по умолчанию, включается в настройках (`experimental.quickSwitch`, `hotkeys.quickSwitch`).
- Избранное, теги и коллекции, этап 8.7: страница «Коллекции» (избранное с порядком, ручные коллекции, сохранённые запросы с автообновлением, добавление перетаскиванием и из списка путей, выгрузка путей в буфер обмена и файл); страница «Теги» с цветами и файлами тега; диалог тегов `Ctrl+T` для одного или нескольких файлов; цветные чипы тегов в списках и карточке файла; `Ctrl+D` закрепляет в быстром поиске и «Обзоре». `POST /api/v1/entries/resolve` — записи индекса по списку путей.
- Имя при переносе на странице «Разбор»: как есть, своё имя или шаблон с подстановками `{имя}`, `{дата}`, `{время}`, `{теги}`, `{папка}`, `{№}`; готовые варианты («Дата в начале», «Теги в конце», …), предпросмотр «Будет: …»; шаблон с `{имя}` запоминается, своё имя без него применяется один раз; расширение сохраняется, недопустимые символы заменяются на «_», одинаковые имена в пачке нумеруются.
- Разбор, этап 17 (срез 17.0): страница «Разбор» — папки-накопители («Загрузки», полученные в мессенджерах и любые другие папки) с числом файлов, их содержимое новыми сверху с выбором нескольких, рабочие папки на клавишах 1–9 и поиск любой папки, дерево подпапок с «Новой папкой», теги с подсказками, «Перенести» (`Ctrl+Enter`) с «Отменить»; накопители и рабочие папки настраиваются там же и хранятся в настройках (раздел `sorting`), папка вне индекса добавляется в него — поиск идёт по всем папкам; `POST /api/v1/sorting/move` переносит одной операцией очереди и сохраняет прежние теги файлов.
- Безопасность, этап 10.4: шаг CI «Уязвимые пакеты» (`dotnet list package --vulnerable --include-transitive`) валит сборку при находке; строка поискового запроса и подсказок — не длиннее 1 000 символов (ответ 400, интерфейс обрезает вставленный огромный текст); `ToString` у адреса сервера и параметров хоста скрывает токен сессии; таблица повторной проверки в ARCHITECTURE, раздел 13.
- Надёжность, этап 10.3: настройки пишутся с резервной копией `settings.json.bak`, и повреждённый файл восстанавливается из неё, а не сбрасывается; о восстановлении базы или настроек после повреждения сообщает полоса в главном окне; нехватка места на диске с базой показывается понятной причиной у корня; после выхода из сна и возврата в сеанс Windows корни перепроверяются (отключённые уходят в офлайн, съёмные и сетевые сверяются, офлайн-корни проверяются сразу); недоступная сетевая папка не задерживает остальные корни — ответа ждут не дольше 5 с; `scripts/soak.ps1` — многочасовой прогон в трее с изменениями файлов, выборками памяти, хендлов и объектов GDI/USER и сверкой индекса с диском.
- Оптимизации, этап 10.2: настройка «Аппаратное ускорение» (GPU и Acrylic в окне поиска, применяется после перезапуска); счётчик в редакторе исключений — «Уберёт из индекса N записей» до сохранения правила (`GET /api/v1/index/exclusions/preview`); окно поиска прогревается после старта, первый показ — 30 мс вместо 182; одинаковые одновременные поиски выполняются один раз; база через минуту простоя закрывает соединения пула и сжимает кэш; миниатюры в плитке грузятся только рядом с видимой областью.
- Измерение, этап 10.1: `scripts/measure.ps1` замеряет бюджеты производительности на портативной копии и сравнивает с ними; `scripts/profile.ps1` снимает трассы и состав памяти; дымовой прогон бюджетов в CI (`tests/DiskApp.Benchmarks -- smoke`); инструменты диагностики — локальные в `dotnet-tools.json`.
- Диагностика, этап 9.5: окно «Что-то пошло не так» для необработанных ошибок с кнопкой «Собрать диагностический архив» (журнал, настройки без секретов, версия, окружение); после аварийного завершения окно открывается при следующем запуске; `--safe-mode` запускает без индексации и Quick Switch и предлагает сбросить настройки; сброс настроек с копией прежнего файла — и в разделе «Данные»; раздел «Журнал» в настройках с фильтром по уровню. Версия 0.5.0.
- Доступность, этап 9.4: у всех кнопок, полей, списков и переключателей есть имена для Экранного диктора (включая части шаблонов FluentAvalonia и строки списков); цели нажатия не меньше 32 px; высокая контрастность Windows включает тему высокой контрастности и сплошной фон поверх выбранной темы; на масштабе 150 % ничего не обрезается — меню навигации сворачивается в узком окне, «Обзор» перестраивается, подписи переносятся.
- Онбординг, этап 9.3: мастер первого запуска (папки для поиска, горячая клавиша с пробой, автозапуск, тема и язык, ход индексации) открывается, пока в индексе нет папок, и проходится заново из «О программе»; обучающие подсказки о горячей клавише, перетаскивании и фильтрах — по одному разу; «Что нового» после обновления; пустые состояния с подсказками в «Обзоре» и «Коллекциях». Новые поля настроек `onboarding.completed`, `onboarding.lastSeenVersion`, `onboarding.tipsShown`.
- Локализация, этап 9.2: интерфейс и сообщения API на русском и английском; язык выбирается в настройках («как в системе», русский, английский) и меняется без перезапуска; числа, даты, размеры и формы слов — по языку. Инструмент `scripts/l10n/L10n.cs` выносит строки в ресурсы.

Корни с параметрами (скрытые, системные, глубина), добавление папки или диска, редактор исключений; запись глобальных сочетаний с проверкой занятости; раздел «Данные» (размеры, пересборка индекса, очистка кэша, выгрузка и загрузка настроек, папка журнала); «О программе» со списком сторонних компонентов; ярлык на рабочем столе. ### Fixed

- Подсказки, меню и списки на мониторе с другим масштабом, чем у основного, больше не обрезаны: на мониторе 100 % рядом с основным 125 % подсказка показывала только первую строку («Добавить рабочую», «D:» вместо пути рабочей папки). Причина — Avalonia 12.1.4 создаёт всплывающее окно на основном мониторе и не пересчитывает масштаб, перенося его к месту показа; теперь окно сразу создаётся на мониторе показа.
- Выход из приложения иногда ждал ровно 5 с: хаб переподключался к останавливающемуся серверу, и тот ждал соединение до таймаута. Теперь сервер при остановке не принимает новые подключения к хабу, приложение закрывает хаб первым; в журнале — время шагов остановки.
- База индекса: редкая ошибка «Соединение писателя не открылось» (`ObjectDisposedException`) при старте и риск, что два потока получат одно соединение SQLite, если пул соединений очищался (освобождение памяти в простое) или к базе одновременно открывалось несколько соединений. Причина — гонка в Microsoft.Data.Sqlite 10.0.12 (dotnet/efcore#39008); выдача соединений из пула и очистка пулов больше не пересекаются. Из-за неё же примерно 1 прогон из 9 тестов Infrastructure падал.
- Индекс: файл, изменившийся во время пересборки индекса раньше, чем сканирование дошло до его папки, оставался без родителя — в «Обзоре» пропадал из своей папки и показывался в корне. Теперь такая запись не считается неизменной, и сканирование восстанавливает связь.
- «Настройки → Входящие»: заголовок «Основная папка-накопитель» был сжат в узкую колонку.
- Авто-теги: самой рабочей папке, добавленной корнем (например, TCI2), нельзя было задать авто-тег — только подпапкам. Теперь — правым щелчком по папке в дереве «Обзора» или «Авто-теги…» в меню чипа на «Разборе»; пункт в меню списка называет папку, к которой относится.
- «Разбор»: при запуске сразу на этой странице файлы накопителей показывались дважды.
- Главное окно не перетаскивалось за заголовок в светлой теме.
- Окно поиска оставалось тёмным с тёмным же текстом после переключения на светлую тему без перезапуска (программная отрисовка).
- Окно «Что-то пошло не так» при быстром наборе в окне поиска: гонка с освобождённым источником отмены.
- Иконка файла с кириллическим расширением не загружалась (ошибка 500 из-за не-ASCII в заголовке ETag).
- Безопасность: проверка «путь внутри корней» смотрела только на первую ссылку — путь через цепочку «junction в другую папку корня, оттуда junction наружу» проходил; теперь цепочка проверяется до конца. Путь устройства вида `\\.\PhysicalDrive0` больше не принимается за сетевой ресурс.
- Поиск: имя в разложенной форме Unicode (NFD — с macOS, из архивов, с сетевых дисков) не находилось запросом с клавиатуры, и наоборот: «café» и «йога» в двух формах теперь находят друг друга, подсветка захватывает букву вместе со знаком; уже проиндексированные имена пересчитываются один раз при открытии базы.
- Поиск: кэш корней (5 с) не сбрасывался — сразу после добавления корня его записи приходили без полного пути; кэши поиска сбрасываются при изменении корней и событиях индекса.
- Индексатор: гонка в диспетчере задач изредка не давала сигнала простоя (зависание до таймаута); задача отключённого корня теперь отменяется и дожидается.
- Журнал: записи HTTP-клиента, Polly и ASP.NET Core уровня сведений больше не пишутся — по десятку строк на каждый запрос к серверу внутри процесса вытесняли события приложения.
- Процесс больше не падает при каждом выходе: оболочка обращалась к уже освобождённому контейнеру служб (дефект появился с Quick Switch на этапе 8.6).
- «Разбор»: рабочая папка, добавленная корнем индекса (папка вне индекса добавляется так сама), помечалась «не найдена», даже если путь задан заново, — у самого корня нет записи в индексе. Теперь путь доступного корня считается найденным.
- «Разбор» показывал «→ папка» с «Отменить» сразу после постановки переноса в очередь, даже если перенос не удался (например, файл открыт в Excel): файл оставался на месте и снова появлялся в списке. Теперь итог показывается, когда операция закончилась; при ошибке файлы возвращаются в список, уведомление называет причину и даёт «Повторить». Файловые операции называют программу, которая держит файл («открыт в программе Microsoft Excel — закройте его там и повторите»), — через диспетчер перезапуска Windows.
- Индекс: папка, добавленная корнем внутри другого корня (например, `TCI2` внутри рабочей папки `10S-417`, которую «Разбор» добавил корнем сам), индексировалась обоими корнями — поиск показывал её файлы по два раза с одним и тем же путём, а сканировали и наблюдали их тоже дважды. Теперь путь принадлежит самому глубокому корню (ADR-0015): внешний корень поддерево внутреннего не индексирует, при добавлении и удалении внутреннего корня записи переходят между корнями с сохранением идентификаторов (статистика, избранное и теги остаются), `root:` и `in:` по внешнему корню или папке находят и файлы вложенных корней, а настройки поясняют, кому принадлежат файлы, когда корень добавляют внутри другого или поверх других.
- Поиск: `tag:` не находил файлы корня, лежащего внутри папки с авто-тегом (`TCI2` внутри `10S-417` с авто-тегом), хотя карточка файла показывала унаследованный тег: после ADR-0015 такие файлы принадлежат вложенному корню. Теперь корни внутри папки с авто-тегом входят в её область целиком, как у `in:`.
