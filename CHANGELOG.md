### Changed

- По умолчанию кандидатов поиска до ранжирования 2 000 вместо 5 000 (замер 3.6); настройка ограничена 100…5 000.
- Портативная копия держит свой одиночный экземпляр, привязанный к папке данных, и может работать рядом с установленной.
- Учёт памяти SQLite выключен: параллельные поиски масштабируются лучше.
- Даты в SQLite хранятся целыми тиками UTC вместо текста ISO 8601 (ADR-0007): база на 1 млн записей уменьшилась с 449 до 389 МБ.
- `.editorconfig`: неиспользуемые `using` и неявные модификаторы доступа — ошибки сборки; приватные статические поля — `_camelCase`; `GenerateDocumentationFile` включён для всех проектов.
- Сочетание быстрого поиска по умолчанию — `Ctrl+Alt+D` с запасными `Ctrl+Alt+F` и `Ctrl+Alt+Space` (ADR-0006); действующее сочетание показывается в настройках и на главной.
- `scripts/publish.ps1` именует сборку `diskapp_v{версия}_{стадия}[_singlefile].exe`, стадия задаётся параметром `-Stage` и попадает в версию сборки.
- Закрепить в быстром поиске — `Ctrl+D` вместо `Ctrl+P`: `Ctrl+P` оставлен для предпросмотра.
- Нейтральный язык ресурсов сборок — русский вместо английского; английский перевод — во вспомогательных сборках `en`.
- Настройки поиска применяются без перезапуска; «Запускаться свёрнутым» действует при запуске вместе с Windows, ручной запуск показывает главное окно.

### Fixed

- Поиск: кэш корней (5 с) не сбрасывался — сразу после добавления корня его записи приходили без полного пути; кэши поиска сбрасываются при изменении корней и событиях индекса.
- Индексатор: гонка в диспетчере задач изредка не давала сигнала простоя (зависание до таймаута); задача отключённого корня теперь отменяется и дожидается.
- Журнал: записи HTTP-клиента, Polly и ASP.NET Core уровня сведений больше не пишутся — по десятку строк на каждый запрос к серверу внутри процесса вытесняли события приложения.
- Процесс больше не падает при каждом выходе: оболочка обращалась к уже освобождённому контейнеру служб (дефект появился с Quick Switch на этапе 8.6).
