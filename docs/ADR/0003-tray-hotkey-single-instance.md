# ADR-0003: Трей, глобальная горячая клавиша, один экземпляр

**Статус:** Принято; поведение щелчков по значку в трее пересмотрено в ADR-0011 (2026-10-11) · **Дата:** 2026-10-10 · **Связано с:** PLAN.md решения 7, 8, 15, вопрос 14; этапы 0.6 (спайк S2), 6.3, 6.4, 6.5

## Контекст

Приложение живёт в трее и должно открывать окно поиска по глобальному сочетанию клавиш из любого места, а повторный запуск (ярлык, «Отправить», протокол `diskapp://`) должен передавать аргументы уже работающему экземпляру. Решение 7 плана запрещает глобальные клавиатурные хуки (антивирусы, надёжность) и предполагало приём `WM_HOTKEY` через `Win32Properties.AddWndProcHookCallback`, которого в Avalonia 12 нет.

## Решение

1. **Трей** — Avalonia `TrayIcon` с `NativeMenu` (Открыть DiskApp, Быстрый поиск, Настройки, Выход); щелчок по иконке переключает окно поиска. Двойного щелчка у `TrayIcon` нет, его роль выполняет пункт «Открыть». Закрытие главного окна прячет его в трей, выход — только из меню.
2. **Горячая клавиша** — `RegisterHotKey` с `MOD_NOREPEAT`; `WM_HOTKEY` принимает собственное message-only окно (`CreateWindowExW` с `HWND_MESSAGE`, оконная процедура `[UnmanagedCallersOnly]`, диспетчеризация по `HWND` в словаре). Окно создаётся на UI-потоке, поэтому сообщения доставляет цикл Avalonia без хуков. Отказ в регистрации (`ERROR_HOTKEY_ALREADY_REGISTERED`, 1409) не фатален: предупреждение в `InfoBar`, поиск остаётся доступен из трея и через `--search`.
3. **Один экземпляр** — именованный `Mutex` `Local\DiskApp.<пользователь>.<сеанс>.Instance`. Второй экземпляр подключается к именованному каналу `DiskApp.<пользователь>.<сеанс>.Pipe` (`PipeOptions.CurrentUserOnly`), отправляет аргументы одной строкой JSON (массив строк, UTF-8, сериализатор из source generator) и завершается с кодом 0 (1 — если канал не ответил за 3 с). Первый экземпляр принимает по одному клиенту за раз в фоне и применяет `StartupArguments` на UI-потоке; запуск без аргументов выводит главное окно на передний план.
4. **Журнал старта** — метки времени от старта процесса: вход в `Main`, готовность Avalonia, показ трея, открытие главного окна, показ окна поиска до первого кадра.

## Последствия

Замеры 2026-10-10 (Release, framework-dependent, тёплый старт, Windows 11, 22 CPU):

| Метка | Время от старта процесса |
|---|---|
| Вход в `Main` | 146 мс |
| Avalonia готова | 601 мс |
| Трей показан | 917 мс |
| Главное окно открыто | 1 482 мс |
| Второй экземпляр: `Main` → аргументы переданы → выход | ≈ 50 мс |

Бюджет «трей < 1 с тёплый» выполнен с небольшим запасом; доля JIT в старте заметна (Avalonia готова лишь к 600 мс), ReadyToRun-сборка (`scripts/publish.ps1`) и ленивое создание главного окна её сокращают. Главное окно в бюджеты не входит: оно не на критическом пути ежедневного сценария.

- Платформенный код живёт в `DiskApp.Desktop/Platform/Windows` под `[SupportedOSPlatform("windows")]`, вызовы охраняются `OperatingSystem.IsWindows()`; на других платформах хоткея нет до SharpHook (этап 12.7).
- На машине разработчика `Ctrl+Alt+Space` занят другим приложением (вероятно, Claude Desktop) — вопрос 14 закрыт ADR-0006 (по умолчанию `Ctrl+Alt+D` с запасными вариантами); настройка сочетания — этап 6.5.
- Два процесса могут писать в один файл журнала (второй экземпляр логирует передачу аргументов), поэтому файловый sink Serilog открыт в режиме `shared`.
- Канал принимает только текущего пользователя: другой пользователь на той же машине получит свой экземпляр.

## Альтернативы

- **SharpHook / `SetWindowsHookEx`.** Глобальный хук клавиатуры: нагрузка на каждый ввод и реакция антивирусов. Отклонено для Windows; остаётся для Linux/macOS.
- **`WM_COPYDATA` для передачи аргументов.** Нужен дескриптор окна и только Windows; именованные каналы кроссплатформенны и работают без окна.
- **Только мьютекс без канала.** Второй экземпляр не смог бы передать `--search` и `--add`.

## Проверка

Тесты `tests/DiskApp.Desktop.Tests` (мьютекс из другого потока, протокол, передача по каналу, повторный клиент, таймаут без сервера). Ручной прогон 2026-10-10: второй и третий экземпляры с `--search` показали окно поиска первого экземпляра и завершились с кодом 0. Открытые пункты: `--add` и `diskapp://` (6.4), настраиваемое сочетание (6.5), подтверждение выхода при операциях (6.3).
