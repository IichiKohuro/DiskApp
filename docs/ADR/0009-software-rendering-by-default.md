# ADR-0009: Программный рендеринг по умолчанию, GPU — настройкой

**Статус:** Принято · **Дата:** 2026-10-11 · **Связано с:** PLAN.md раздел 8 (бюджет «Память в простое < 150 МБ»), этап 10.2, ADR-0002

## Контекст

Замер этапа 10.1 показал память в простое 343–384 МБ рабочего набора при бюджете 150 МБ. Снимок кучи и счётчики среды показали, что управляемые объекты занимают 26 МБ, а память сборщика — около 50 МБ. Остальное нативное.

Опыт на одной сборке с одинаковым сценарием дал такой частный рабочий набор (столбец «Память» Диспетчера задач, которым задан бюджет): в трее после поисков и окна поиска / через минуту простоя после главного окна.

| Рендеринг Avalonia | Частный рабочий набор, МБ | Потоков | Первый показ окна поиска |
|---|---|---|---|
| ANGLE + Direct3D 11 (по умолчанию в Avalonia), композиция WinUI | 239 / 206 | 73 | 182 мс |
| ANGLE, композиция DirectComposition | 225 / 219 | 72 | — |
| ANGLE, поверхность перенаправления | 236 / 227 | 74 | — |
| OpenGL (WGL) | 179 / 171 | 29 | — |
| Программный (Skia на CPU) | 125 / 117 | 26 | 100 мс |

Около 90 МБ и полсотни потоков приносит сам GPU-драйвер, способ композиции почти не влияет. Нагрузка на процессор при прокрутке длинного списка одинакова: 4 % одного ядра программно и 5 % с GPU.

Правило проекта: бюджеты производительности не ослабляются ради функции, функция уходит за флаг (CLAUDE.md, PLAN.md раздел 8).

## Решение

1. **По умолчанию окна рисуются программно:** `Win32PlatformOptions.RenderingMode = [Software]`.
2. **Аппаратное ускорение — настройка** `appearance.hardwareAcceleration` («Внешний вид» → «Аппаратное ускорение»), выключена по умолчанию. Она применяется после перезапуска: рендеринг выбирается до запуска Avalonia, а контейнер настроек ещё не собран. Поэтому `RenderingChoice` читает одно поле прямо из `settings.json`, нечитаемый файл означает значение по умолчанию. Страница настроек показывает, что нужен перезапуск, если настройка расходится с тем, как приложение запущено.
3. **Переменная `DISKAPP_RENDERING=gpu|software`** переопределяет настройку для проверки и сравнения.
4. Вместе с этим база отдаёт память при простое: через минуту без чтений и записей закрываются соединения пула вместе с кэшем страниц, писатель выполняет `PRAGMA optimize` и `shrink_memory`. Кэш 64 МБ на соединение сохраняется на время работы: с 8 МБ запросы с фильтрами на 1 млн записей выходят из бюджета поиска.

## Последствия

- Память в простое укладывается в бюджет: около 100 МБ частного рабочего набора.
- Без ускорения в окне поиска нет размытия Acrylic: окно получает сплошной фон темы. Mica главного окна и остальные стили не меняются. Кто хочет Acrylic, включает ускорение и платит памятью.
- Первый показ окна поиска быстрее: не нужна инициализация GPU-поверхности.
- Если в будущем появятся тяжёлые анимации или эффекты, программный рендеринг станет заметно дороже. Тогда решение пересматривается замером `scripts/measure.ps1`.

## Альтернативы

- **GPU по умолчанию и урезание рабочего набора при простое (`EmptyWorkingSet`).** Цифра в Диспетчере задач падает, но выделенная память остаётся, страницы возвращаются при первом обращении. Это прячет расход, а не уменьшает его.
- **OpenGL (WGL).** Лучше ANGLE, но выше бюджета, и на части видеодрайверов OpenGL в Windows работает хуже Direct3D.
- **Ослабить бюджет до 250 МБ.** Противоречит правилу проекта; вернуться к этому можно только записью в журнале плана и новым ADR.
