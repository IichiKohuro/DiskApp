# ADR-0013: Модуль уведомлений и напоминаний

**Статус:** Принято · **Дата:** 2026-10-11 · **Связано с:** [VISION.md](../VISION.md) пункты 3–5, PLAN.md решения 20 и 24, вопрос 18, этапы 16.1, 17 и 21

## Контекст

Исходное решение 20 и этап 17.6 описывали планировщик «умного момента» только для напоминаний о разборе. Детектор занятости в нём был очень подробным:

- простой ввода и состояние уведомлений Windows;
- звонок — по использованию микрофона и камеры (реестр `CapabilityAccessManager`);
- категория активного окна и частота переключений, интенсивность ввода;
- обучение по реакциям пользователя.

Другие части плана придумывали свои уведомления каждая сама:

- toast о завершении операций — этап 12.5;
- напоминание о давней резервной копии и сбое копирования — этап 16.1;
- сводка автоправил — этап 17.5.

Видение выделяет «Напоминания/Уведомления» отдельным модулем. Пользователь хочет и свои напоминания, «было бы неплохо».

## Решение

1. **Один модуль на всё приложение.**
   - `INotificationService` — показать уведомление: вид, заголовок, текст, действия, важность.
   - `IReminderScheduler` — «напомни тогда-то»: в точное время или в удобный момент.

   Разбор, авторазбор, операции, резервные копии, ошибки индекса и свои напоминания идут только через модуль. Лимиты частоты, «не беспокоить» и часы тишины живут в одном месте.
2. **Канал — по нарастанию:**
   1. значок и подсказка в трее — всегда;
   2. тихая карточка у области уведомлений — собственное окно в стиле Fluent: не модальное, без звука, не забирает фокус, с кнопками действий. Закрывается щелчком или через несколько секунд;
   3. `InfoBar` в главном окне, если оно открыто.

   Системные уведомления Windows (toast) пока не используются. Для неупакованного приложения им нужны регистрация AUMID с ярлыком и API WinRT, то есть смена целевой платформы. Вернуться к ним можно после установщика (этап 11), вопрос 18.
3. **«Умный момент» — сначала простой.** Сигналы занятости:
   - простой ввода (`GetLastInputInfo`);
   - состояние уведомлений Windows (`SHQueryUserNotificationState`: полный экран, презентация, «Не беспокоить»);
   - блокировка и разблокировка сеанса;
   - часы тишины.

   Хороший момент — возвращение к компьютеру после простоя и пары минут лёгкой активности или разблокировка сеанса. «Отложить» без срока даёт нарастающую отсрочку: 45 минут → 1,5 часа → 3 часа → следующий день. Действуют лимиты на час и на день.

   Распознавание звонков по микрофону и камере, категории окон и обучение по реакциям — опционально. Их делают, только если ежедневное использование покажет неудачные моменты напоминаний.
4. **Свои напоминания (опц.).**
   - «Напомнить…» у файла, папки или просто с текстом.
   - Срок: «через час», «вечером», «завтра», дата и время. Режим: в точное время или в удобный момент.
   - Напоминания хранятся на сервере (в базе), переживают перезапуск и видны другим клиентам. Пропущенные, пока приложение было закрыто, показываются при запуске.
   - Карточка напоминания открывает файл. Список напоминаний — в главном окне.
5. **Настройки** — один раздел «Уведомления»:
   - виды уведомлений вкл./выкл.;
   - настойчивость: редко, обычно, часто;
   - часы тишины;
   - учитывать «Не беспокоить» Windows;
   - «не беспокоить» в DiskApp на час или до завтра.

## Последствия

- Приложение не засыпает пользователя уведомлениями из разных мест: лимиты общие.
- У собственной карточки нет истории в Центре уведомлений Windows. Если она понадобится, будет список последних уведомлений в приложении (опц.).
- «Не беспокоить» Windows карточка соблюдает сама, по `SHQueryUserNotificationState`. Это проверяется тестами планировщика с подменёнными сигналами.
- Планировщик живёт в `DiskApp.UI`, детектор занятости — в `DiskApp.Desktop`. Клиентам Android и Web понадобятся свои детекторы. Сами напоминания на сервере общие.

## Альтернативы

- **Toast-уведомления Windows сразу.** Родной вид, Центр уведомлений, системная фокусировка. Но нужны регистрация AUMID, ярлык в портативном режиме и смена целевой платформы на `net10.0-windows10.0.x`. Отложено до установщика.
- **Оставить 17.6 как есть.** Только разбор, тяжёлый детектор и отдельные уведомления у каждого этапа. Дублирование кода и разные лимиты.
- **Сторонняя библиотека уведомлений.** Новая зависимость ради окна, которое делается своими контролами.

## Проверка

- Детерминированные тесты планировщика с подменяемыми часами и сигналами:
  - «занят → отложил → освободился → напомнили один раз»;
  - «три отсрочки → следующий день»;
  - лимит в день;
  - «Не беспокоить» блокирует показ;
  - пропущенное напоминание показывается при запуске.
- За две недели ежедневного использования — ни одного уведомления, которое пользователь счёл неуместным (FEEDBACK.md).
