# Architecture Decision Records

Здесь фиксируются архитектурные решения DiskApp: почему выбран именно этот путь, какие альтернативы рассматривались и чем мы за это платим. Краткая таблица решений — в [PLAN.md](../../PLAN.md), раздел 2; ADR раскрывают их подробнее и хранят историю.

## Правила

- Один ADR — одно решение или одна связанная группа решений.
- Номер сквозной, четырёхзначный: `0001-kebab-case-title.md`.
- Статусы: **Предложено**, **Принято**, **Принято, ожидает проверки** (спайком или первым использованием), **Заменено ADR-NNNN**, **Отклонено**.
- Принятый ADR не редактируется по смыслу. Если решение меняется, пишется новый ADR, а старый получает статус «Заменено».
