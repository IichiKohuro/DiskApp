# ADR-0006: Сочетание клавиш быстрого поиска по умолчанию

**Статус:** Принято · **Дата:** 2026-10-10 · **Связано с:** PLAN.md решение 15, вопрос 14; ADR-0003; этап 6.5

## Контекст

Решение 15 выбрало `Ctrl+Alt+Space`: `Alt+Space` занят системным меню окна и PowerToys Run, `Ctrl+Space` конфликтует с IME. На машине пользователя `RegisterHotKey` для `Ctrl+Alt+Space` возвращает `ERROR_HOTKEY_ALREADY_REGISTERED` (1409): сочетание держит другое приложение, вероятно Claude Desktop. Пользователь попросил выбрать свободное.

Проверка 2026-10-10 на его машине (`RegisterHotKey` с `MOD_NOREPEAT`, затем `UnregisterHotKey`):

| Сочетание | Итог |
|---|---|
| `Ctrl+Alt+Space` | занято (1409) |
| `Ctrl+Win+Space`, `Win+Shift+Space` | заняты системой (переключение раскладки) |
| `Ctrl+Alt+D`, `Ctrl+Alt+F`, `Ctrl+Alt+K`, `Ctrl+Alt+Q`, `Ctrl+Alt+S`, `Ctrl+Alt+Enter`, `Ctrl+Alt+Home`, `Ctrl+Alt+`` | свободны |
| `Ctrl+Shift+Space`, `Alt+Shift+Space`, `Win+Alt+Space` | свободны, но `Ctrl+Shift+Space` занят в Visual Studio и Excel, `Alt+Shift` переключает раскладку, `Win+Alt` — семейство Xbox Game Bar |

## Решение

1. **По умолчанию `Ctrl+Alt+D`**: D как DiskApp, нажимается одной рукой, не используется системой и не совпадает с ходовыми сочетаниями Visual Studio, браузеров и Проводника.
2. **Запасные варианты по порядку**: `Ctrl+Alt+F`, затем `Ctrl+Alt+Space`. Оболочка регистрирует первое свободное; если сработал запасной вариант, главное окно показывает информационный `InfoBar`, а настройки и подсказки на главной странице выводят действующее сочетание (`HotkeyStatus`). Если не удалось ни одно, предупреждение остаётся, поиск доступен из трея и через `--search`.
3. Настраиваемое сочетание (модель `Hotkey`, сохранение) — этап 6.5, как и планировалось.

## Последствия

- Решение 15 плана меняется: `Ctrl+Alt+D` вместо `Ctrl+Alt+Space`; README, ADR-0003 и подсказки интерфейса приведены в соответствие.
- `Ctrl+Alt+<буква>` на части европейских раскладок равно `AltGr+<буква>` и может печатать символ; для русской и английской раскладок это не так. Пользователям с такими раскладками понадобится настройка из 6.5.
- Запасной порядок делает поведение на чужой машине предсказуемым: сочетание меняется только при конфликте, и пользователь видит, какое действует.

## Альтернативы

- **Оставить `Ctrl+Alt+Space` и просить пользователя освободить его в другом приложении.** Переносит проблему на пользователя при каждом новом конфликте.
- **`Ctrl+Shift+Space`.** Свободно глобально, но перехватывало бы подсказку параметров в Visual Studio.
- **Сочетания с `Win`.** `Win+Space` и соседние заняты переключением раскладки, `Win+Alt` — Game Bar.

## Проверка

Пробник `RegisterHotKey` на машине пользователя (таблица выше), журнал приложения («Оболочка запущена … хоткей Ctrl + Alt + D»), пункт чеклиста QA про конфликт сочетания. Пересмотр — при появлении настройки в 6.5 и по отзывам dogfooding.
