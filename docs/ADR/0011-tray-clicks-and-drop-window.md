# ADR-0011: Щелчки по значку в трее и окно Drag&Drop

**Статус:** Принято, ожидает проверки (спайк в начале этапа 18.1) · **Дата:** 2026-10-11 · **Связано с:** [VISION.md](../VISION.md) пункт 1, PLAN.md решения 8 и 21, этап 18, ADR-0003, ADR-0006

## Контекст

Сейчас (этап 6.3, ADR-0003) щелчок по значку в трее открывает и прячет быстрый поиск. Двойного щелчка нет: главное окно открывается пунктом меню «Открыть».

Видение задаёт другое поведение:

- **двойной щелчок** (и свой хоткей) — главное окно;
- **щелчок** (и свой хоткей) — окно Drag&Drop с двумя областями. Область 1: брошенные файлы падают в основную папку-накопитель. Область 2: открывается настройка перемещения в рабочую папку, её делаем последней;
- **правый щелчок** — меню.

Быстрый поиск остаётся на своём хоткее.

У Avalonia `TrayIcon` есть только событие `Clicked`. Отличить одиночный щелчок от двойного можно только по времени между щелчками.

## Решение

1. **Щелчки.**
   - Одиночный щелчок открывает окно Drag&Drop, но не сразу: приложение ждёт системный интервал двойного щелчка (`GetDoubleClickTime`, по умолчанию 500 мс). Если за это время пришёл второй щелчок, это двойной щелчок: открывается главное окно, а окно Drag&Drop не показывается.
   - Повторный щелчок при открытом окне Drag&Drop прячет его.
   - Правый щелчок — меню, как сейчас. В меню добавляется пункт «Окно Drag&Drop».
2. **Как распознаётся двойной щелчок.** Основной путь — два события `Clicked` в пределах интервала. Если спайк покажет, что Avalonia не передаёт второй щелчок, значок рисуется собственным `Shell_NotifyIcon` в уже существующем message-only окне `MessageWindow`. Там видны `WM_LBUTTONUP` и `WM_LBUTTONDBLCLK`, а меню остаётся прежним. Итог спайка дописывается сюда.
3. **Горячие клавиши.** Появляются две новые настройки:
   - `hotkeys.mainWindow` — показать или спрятать главное окно;
   - `hotkeys.dropWindow` — показать или спрятать окно Drag&Drop.

   Обе записываются в настройках тем же контролом, что и быстрый поиск, с проверкой конфликтов. Значения по умолчанию выбираются пробником свободных сочетаний на машине пользователя, как в ADR-0006 (PLAN.md, вопрос 17). Быстрый поиск остаётся на `Ctrl+Alt+D` и в меню трея.
4. **Окно Drag&Drop.**
   - Небольшое окно в стиле окна быстрого поиска, создаётся заранее для мгновенного показа.
   - Стоит у области уведомлений над панелью задач, с учётом её положения, поверх всех окон.
   - **Не прячется при потере фокуса**: чтобы взять файлы, пользователь переключается в Проводник или мессенджер. Окно прячется по `Esc`, по кнопке закрытия, повторным щелчком по значку или хоткеем, а также через несколько секунд после броска, если пользователь не взаимодействует с итогом.
5. **Область 1 — «Бросить в накопитель».**
   - Файлы попадают в основную папку-накопитель: отметка «основная» в списке `sorting.inboxes`, по умолчанию «Загрузки». Настройка `add.inboxPath` сливается с этой отметкой: остаётся одно понятие.
   - Действие — как в Проводнике: на том же томе файлы перемещаются, с другого тома копируются. `Shift` — переместить, `Ctrl` — скопировать. Над областью при перетаскивании видно действие: «Переместить в „Загрузки“» или «Скопировать в „Загрузки“».
   - Конфликт имён — «оставить оба».
   - Итог — строка «3 файла → Загрузки» с «Отменить». Файлы появляются на странице «Разбор».
   - Источник может лежать вне корней индекса (например, «Рабочий стол»). Такой перенос сервер принимает только от клиента в этом же процессе — так же, как предложено для обзора в вопросе 16. Для удалённых клиентов этапа 13 правило `RootGuard` не меняется.
6. **Область 2 — «Разложить по рабочей папке»** (этап 18.3, последней).
   - Брошенные файлы открывают компактную панель переноса со страницы «Разбор»: рабочая папка 1–9, подпапка, имя, теги.
   - Она заменяет отдельное окно разбора `TriageWindow` из исходного этапа 17.3.
   - До этапа 18.3 окно показывает только область 1.

## Последствия

- Одиночный щелчок по значку откликается с задержкой около полусекунды. Это цена двойного щелчка. Хоткей окна Drag&Drop срабатывает без задержки.
- Быстрый поиск больше не открывается щелчком по значку. Новое поведение объясняют подсказка после обновления и «Что нового».
- Окно, которое не прячется при потере фокуса, нужно явно закрывать. Поэтому оно небольшое, не перекрывает рабочую область и само уходит после броска.
- Перенос из-за пределов корней расширяет доступ сервера к диску для локального клиента. Ограничение по клиенту проверяется тестами.

## Альтернативы

- **Открывать окно Drag&Drop сразу и закрывать его на втором щелчке.** Окно мелькало бы при каждом двойном щелчке.
- **Замена `TrayIcon` на H.NotifyIcon** (альтернатива решения 8). Новая зависимость ради одного события. Собственный `Shell_NotifyIcon` в существующем окне сообщений дешевле, если он вообще понадобится.
- **Оставить щелчок за быстрым поиском, окно Drag&Drop — только хоткеем.** Противоречит видению.
- **Бросать файлы прямо на значок в трее.** Значок в области уведомлений не принимает перетаскивание.

## Проверка

- Спайк в начале 18.1: приходят ли два `Clicked` на двойной щелчок; задержка одиночного щелчка на машине пользователя.
- Ручной чеклист: щелчок, двойной щелчок и правый щелчок; оба хоткея; бросок из Проводника на том же и на другом диске; бросок с `Shift` и `Ctrl`; отмена.
