# ADR-0008: Quick Switch через Win32-сообщения стандартному диалогу файлов

**Статус:** Принято, ожидает проверки (ручной прогон в Блокноте, Word, браузере и VS Code) · **Дата:** 2026-10-11 · **Связано с:** PLAN.md вопрос 4, решение 7, этап 8.6, риск «Quick Switch зависит от внутренностей системных диалогов»

## Контекст

Этап 8.6 просит помочь при сохранении: человек в диалоге «Сохранить как» любой программы нажимает сочетание клавиш, выбирает папку в быстром поиске DiskApp, и диалог переходит в неё. Публичного API «перевести чужой диалог в папку» у Windows нет. Диалог принадлежит другому процессу, поэтому `IFileDialog::SetFolder` недоступен.

По вопросу 4 PLAN.md функция экспериментальная и стоит за флагом. Решение 7 запрещает клавиатурные хуки: перехватывать клавиши внутри чужого диалога нельзя, остаётся глобальное сочетание через `RegisterHotKey`.

## Решение

1. **Тот же путь, что у человека.** В поле имени файла записывается путь к папке (`WM_SETTEXT`), диалогу отправляется команда «ОК» (`WM_COMMAND` с `IDOK`). Для существующей папки стандартный диалог не сохраняет файл, а переходит в неё. После ответа на команду исходное имя файла возвращается в поле, через 150 и 400 мс оно проверяется ещё раз.
2. **Распознавание диалога.** Подходит окно класса `#32770`, внутри которого есть список файлов Проводника (`DUIViewWndClassName` или `SHELLDLL_DefView`) и поле имени файла. Поле ищется так: `Edit` внутри элемента с идентификатором `cmb13` (`0x47C`), затем `Edit` с идентификатором `edt1` (`0x480`), затем первое поле внутри видимого `ComboBoxEx32` или `ComboBox`. Окна сообщений и другие диалоги того же класса не подходят.
3. **Синхронная команда вместо нажатия Enter.** `WM_COMMAND` отправляется через `SendMessageTimeoutW`: диалог разбирает поле, пока обрабатывает сообщение. Поэтому возврат имени файла не обгоняет переход, и файл не сохранится в старую папку. Нажатие Enter через `PostMessage` отложило бы обработку, и момент возврата имени пришлось бы угадывать.
4. **Защита и откат.** Путь передаётся, только если папка существует, иначе «ОК» сохранил бы файл с таким именем. Все сообщения идут с `SMTO_ABORTIFHUNG` и таймаутом, поэтому зависший диалог не останавливает DiskApp. Если диалог не принял текст или команду, имя файла возвращается, путь копируется в буфер обмена, и быстрый поиск предлагает вставить его вручную.
5. **Флаг и сочетание.** Флаг `experimental.quickSwitch` выключен по умолчанию, сочетание `hotkeys.quickSwitch` по умолчанию `Ctrl+Alt+G`. Сочетание регистрируется, только пока функция включена, и без запасных: если оно занято, переключатель в настройках не включается и показывает причину.
6. **Выбор папки — режим быстрого поиска.** Запрос начинается с `type:folder`. `Enter` на папке отдаёт её, на файле — его папку. `Esc` отменяет выбор одним нажатием, обычный показ поиска тоже отменяет незавершённый выбор.

## Последствия

- Работает в программах со стандартным диалогом `IFileDialog` (Windows Vista и новее) и со старыми диалогами в стиле Проводника. Блокнот, Word, браузеры на Chromium и VS Code используют `IFileDialog`.
- Не работает в программах со своими диалогами: Java Swing, часть приложений на Qt и GTK, некоторые установщики. Не работает в диалоге процесса, запущенного от администратора, если DiskApp запущен без повышения: Windows блокирует сообщения от процессов с меньшей целостностью (UIPI).
- Опирается на внутреннее устройство диалога: идентификатор `cmb13` и классы окон. Обновление Windows может их изменить, поэтому функция остаётся экспериментальной.
- Если сочетание нажато вне диалога, быстрый поиск показывает подсказку и ничего не делает с чужими окнами.

## Альтернативы

- **UI Automation (`IUIAutomation`).** Даёт поле имени файла через `ValuePattern` и кнопку через `InvokePattern`, но требует COM-обвязки на сотни строк без генератора, медленнее на первом обращении (сотни миллисекунд на построение дерева) и тоже зависит от внутренних имён элементов. Оставлен запасным путём, если Win32-подход сломается после обновления Windows.
- **Нажатие Enter через `PostMessage` или `SendInput`.** Асинхронно: нельзя надёжно понять, когда возвращать имя файла. `SendInput` к тому же зависит от того, какое окно активно в момент нажатия.
- **Адресная строка диалога** (`Breadcrumb Parent` → `ToolbarWindow32` → поле ввода). Требует сначала включить режим редактирования адреса и сильнее зависит от версии Windows.
- **Внедрение в процесс диалога** (`SetWindowsHookEx`, DLL-инъекция) и вызов `IFileDialog::SetFolder` изнутри. Отклонено: противоречит решению 7, требует нативной DLL под каждую разрядность и выглядит для антивирусов как вредоносное поведение.

## Проверка

- Автотест `FileDialogBridgeTests.NavigateAsync_RealSaveDialog_SwitchesFolderAndKeepsFileName` (включается переменной `DISKAPP_SHELL_TESTS=1`) открывает настоящий `SaveFileDialog` в отдельном процессе, переводит его в папку и нажимает «Сохранить». Диалог возвращает путь в новой папке с исходным именем файла. Прогон 2026-10-11 зелёный на Windows 11 Pro 26200.
- Ручной прогон по `docs/QA_CHECKLIST.md` в Блокноте, Word, браузере и VS Code. До него функция остаётся за флагом. Если какая-то из этих программ не сработает, это запишется сюда ограничением, и будет рассмотрен путь через UI Automation.
